# Security Policy

## Supported versions

Security fixes target the latest Resonance release and the current `main` branch. Older versions may not receive fixes.

## Report a vulnerability

Use [GitHub private vulnerability reporting](https://github.com/manusco/resonance/security/advisories/new). Do not open a public issue for a suspected vulnerability.

Include:

- the affected version, file, skill, or command;
- the security impact;
- the smallest safe reproduction;
- any known mitigations or suggested fix;
- whether the issue is already public.

Remove credentials, personal data, and unrelated private project content. The maintainer will review the report and coordinate disclosure through the private advisory.

## Scope

Reports should show a security impact in Resonance code, generated tooling, upgrade behavior, or documented security controls. A model giving an incorrect answer is not by itself a vulnerability unless Resonance creates or misrepresents a security boundary.
