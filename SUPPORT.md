# Support

Use the route that matches the request. This keeps questions separate from work that needs a code change.

## Usage questions

Ask in [GitHub Discussions](https://github.com/manusco/resonance/discussions). Include the Resonance version, agent host, operating system, and the smallest safe example that explains the question.

## Bugs and proposals

- Use the [bug report](https://github.com/manusco/resonance/issues/new?template=bug-report.yml) for a reproducible defect.
- Use the [skill field report](https://github.com/manusco/resonance/issues/new?template=skill-field-report.yml) when a skill does not meet its documented contract.
- Use the [improvement proposal](https://github.com/manusco/resonance/issues/new?template=feature-request.yml) for a focused change request.

Search existing issues and discussions first. Remove secrets, personal data, and private project content from every report.

## Security

Follow [SECURITY.md](SECURITY.md). Report suspected vulnerabilities privately. Do not post them in an issue or discussion.

## Support scope

The public support channels cover Resonance installation, upgrades, framework behavior, and contribution questions. They do not provide private project implementation or a response-time guarantee.
