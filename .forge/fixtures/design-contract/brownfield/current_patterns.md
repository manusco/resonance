# Example workspace: current table patterns

There is no approved design contract for these screens. These are observations from the current implementation.

| Screen | Current filter pattern | Primary task | Reference |
|---|---|---|---|
| Customers | Search and status filters in a top toolbar | Find a customer quickly, then inspect a record | This observation in `current_patterns.md` |
| Invoices | Persistent filter sidebar with date, account, region, and payment state | Reconcile a batch by combining several criteria | This observation in `current_patterns.md` |
| Audit log | Time-range and actor chips above the table | Find a recent event and identify its actor | This observation in `current_patterns.md` |

The proposed feature is Vendors, an ordinary record lookup and inspection table. It has search and status filters and no batch-reconciliation workflow.

The existing design owner is the product design lead. A durable default needs that owner's approval. This fixture contains no approval for the proposed Vendors pattern.
