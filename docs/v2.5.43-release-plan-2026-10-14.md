1. Preserve the initial tracked diff and untracked file hashes outside the repository. Inventory all existing plans, reports, research notes, templates, generated skills, eval fixtures, manifests, and mirrors. Inspect fingerprint scan results before staging.
2. Prepare this release on `codex/release-v2.5.43`, retaining the existing dirty worktree. Review accumulated improvements against their plans and evidence, reconcile independent UX and reasoning reviews, and apply only canonical fixes approved by the release integrator.
3. Confirm Forge generation is current. Run release gates from `.github/workflows/release.yml`: strict skill and library validation, doc drift, all eval structural checks, orchestration check, repository tests, fingerprint scan against the last available release tag, and release metadata validation. Structural eval checks do not establish behavioral lift.

6. Create a PR to `main`, wait for required CI and review, then merge through repository policy. After merge, run the documented `workflow_dispatch` release workflow on `main`; it creates the tag and GitHub Release with generated notes, manifest, and checksums. Do not create a local tag or bypass that workflow.
