# Evidence Kernel

Resonance uses a small file-backed kernel for work that prose cannot make safe.
It records contracts, approvals, execution receipts, evidence receipts, and
ledger entries. It does not schedule work, run a daemon, or replace the skills.

## Boundary

The kernel lives in `.forge/kernel/` and has six modules:

- `contracts.py`: schema version, stable hashes, and receipt validation.
- `evidence.py`: append-only state writes, file locks, stale-hash rejection, and achievement gates.
- `transitions.py`: legal goal state transitions.
- `ledger.py`: typed ledger parsing and status-aware recall.
- `manifest.py`: machine-readable skill ownership contracts.
- `__init__.py`: package marker only.

## Rule

A goal can reach `achieved` only when current accepted evidence covers each
approved acceptance criterion and that evidence points to an execution receipt
recorded by the current goal run. A model summary or stale plan cannot complete a
goal. Routine accepted evidence does not require human approval; overrides do.

## Public Contracts

- `SkillManifest`
- `ActionRequest`
- `ApprovalReceipt`
- `ExecutionReceipt`
- `EvidenceReceipt`
- `LedgerEntry`

The first shipped implementation validates all six contract shapes. It records
trusted local execution receipts through the goal loop before accepting evidence.
Adapters that run external tools should emit the same `ExecutionReceipt` shape.

## Generated Files

`docs/skill-manifest.json` is generated by:

```bash
py .forge/kernel/manifest.py
```

`validate_library.py` fails if the manifest is stale. The first manifest is a
catalog contract. It lists authority and declared invokes, but it does not yet
claim complete write-set ownership because most skills do not declare explicit
write sets. Consequential ownership becomes enforceable only where skills add
explicit metadata.
